# Architecture (target)

Aspirational shape for the hosted, multi-tenant platform. The current repo is a
skeleton; this is where it's going.

## Request flow

```
Browser ──HTTPS──▶ TLS proxy ──▶ FastAPI ──▶ tenant-scoped service/CRUD
   ▲                                │              │
   │                                │              ▼
   └────── HTML ◀── Jinja2 ◀────────┘         SQLAlchemy ──▶ PostgreSQL
                    (HTMX fragments)
```

- Server-rendered Jinja2 with HTMX for interactivity (as in Breakout Billing).
- Every request runs in a **tenant context**; every tenant-owned query is scoped
  by `tenant_id`.

## Multi-tenancy

- **Shared-database, shared-schema** with a `tenant_id` column on every
  tenant-owned table (simplest to operate; enforce scoping in a single place —
  a query helper / session dependency — not ad hoc per route).
- Alternatives (schema-per-tenant, db-per-tenant) are heavier; only revisit if a
  customer contract demands hard isolation.

## Roles

`client`, `therapist`, `admin` — distinct surfaces and permissions. Auth is real
multi-user (not the single shared password of the local tool). Sessions carry
the user, their role, and their tenant.

## Data model (starting point)

```
Tenant ──1:N──▶ User (role: client | therapist | admin)
```

Domain entities (`Client`, `Appointment`, `Payment`, `Provider`, superbill/
statement generation, CPT catalog, money math) come from **`breakout-core`**
(`INTEGRATION.md`) — not reimplemented here. The platform adds tenant scoping,
client-facing scheduling/intake, and the payment model chosen in `DECISIONS.md`.

## Schema ownership

Alembic owns the schema; `run_migrations()` runs `alembic upgrade head` at
startup. Prefer nullable columns; review autogenerated migrations.

## Deployment

Hosted under a BAA (AWS/GCP/Azure), Postgres managed, TLS terminated in front,
secrets from the environment. Encryption-at-rest is the managed host's job (unlike
the local tool, which leans on FileVault).
